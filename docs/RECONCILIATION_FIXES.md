# Reconciliation (1-Oct-2026) -> what the model now does

Source: "Sentinel Q - Reconciliation of Two Implementations" (NAVIN GANESH P). The "team-built" card in that document is this model; its section 7 lists
seven fixes "in build order". `sentinelqv1.pdf` (this model's own output) shows the same symptoms: 14 of 29 Flags, all carrying a -20 "regulatory action",
no +2 or -1 anywhere, share-price language in the sentiment text, and corporate-action counts inflated by repeat headlines (375 headlines).

| # | Fix (s7) | What the code does now | Where | Test |
|---|---|---|---|---|
| 1 | Never backdate a live search; use an archive | `--news auto` picks GDELT (dated archive) for a past as-of date, the live index only for a current date. A live index with a past date is **refused** unless `--allow-live-backdate`, and is then stamped "live index, cut-off X - NOT a point-in-time backtest" on page 1, in `run_meta.json` and the audit. A separate 12-month **results pass** brings the full-year results prints into sentiment even when the latest-N pull collapses onto the last weeks. | `retrieval.py`, `ingest/*.fetch_fundamentals`, `pipeline._fetch_stock`, `pdf.py` | `test_backdated_*`, `test_fundamentals_pass_*` |
| 2 | Verification gate before any penalty | Every governance item must answer: **subject** (company / victim / lender / peer-sector / macro / shareholders), **occurred at the company?**, **severity**, plus action stage, amount, and for people items direction + role tier. Hard rules: appointment / promotion / reappointment / planned succession is never an exit; macro or sector policy is never company regulatory action; a victim is not the subject; a resolved matter is not a live overhang; a notice with no order is a -10 overhang, not -20. An item missing these answers fails validation (retried once, then dropped with the reason). A text-level safety net backs the model for people and macro/victim cases. | `classify.py`, `validate._check_gate`, `score.gate` | `test_direction_*` (7 rows), `test_subject_*` (4), `test_eicher_*`, `test_bank_of_maharashtra_*` (2), `test_nestle_*` (1) |
| 3 | Write the conventions down | In `rubric/rubric_v1.json` -> `governance.conventions`: materiality floor Rs 10 cr (non-integrity matters below it sit in the -5 procedural band), severity caps, 7-day same-event de-duplication **within a family** (regulatory with regulatory, people with people - a fraud probe and the CFO's termination are separate), memory discount only if no in-window penalty exists, one corporate action per declaration (dividend repeats collapse). | `rubric_v1.json`, `score.governance`, `lint.unique_actions` | `test_memory_discount_*`, `test_corporate_action_repeat_*`, `test_materiality_floor_*` |
| 4 | Reconcile the universe before every run | The stock list is hashed and diffed against the last confirmed run (`.cache/universe_lock.json`). A change refuses to run until `--confirm-universe`; `--expect-count N` guards the size. | `universe.py`, `cli.py` | `test_universe_change_refuses_until_confirmed` |
| 5 | Ban price language from sentiment | Headlines that are only about the share price become `price_move` (sentiment 0, excluded); the classifier prompt forbids price reasoning; price sentences are stripped from sentiment commentary and logged in the audit. Price stays in the context overlay. | `lint.py`, `pipeline._label_stock`, `narrate.py` | `test_price_only_*`, `test_pipeline_relabels_*` |
| 6 | Minimum evidence standard | Fewer than 8 relevant articles, or no results / earnings / guidance item in the 12-month window -> sentiment reports **n/a (Insufficient Data)**, never a forced +1 or 0. The span of dates actually covered is measured and a collapsed window is flagged. Thresholds are in the rubric. | `score.evidence_standard`, rubric `sentiment` | `test_insufficient_data_*`, `test_pipeline_reports_n_a_*` |
| 7 | Union-then-rescore | `python -m sentinelq merge RUN_A RUN_B --out DIR` takes the union of two runs' evidence (plus human-verified events), scores **once** under one rubric and writes `MERGE_RECORD.md`. `portfolio/verified_events.csv` holds the events verified in s6 (with sources) and is merged into every run. | `tools.merge`, `verified.py` | `test_merge_is_union_*`, `test_verified_events_reproduce_the_reconciled_governance_scores` |

## Reproduced exactly
With only the verified events, the governance scores match s6 of the Reconciliation: **Nippon 65 (Flag), Kajaria 82, Bosch 83, Honeywell 92, Marico 87, Bank of Maharashtra 95**.

## Not done / still open (be aware)
* **BSE/NSE filings** are not ingested (the Reconciliation names them as an archival source). The dated archive used is GDELT; whether it restores the full-year results prints for every name has not been run here (GDELT was unreachable from the build environment).
* **"0.1% of revenue"** floor needs revenue data; only the Rs 10 cr floor is implemented.
* **Provisional** verified events (Honeywell, Marico x2, Natco, Bank of Maharashtra, Zen, Nippon EPF) carry the reconciliation's own caveat "confirm from filing". Events with no date are "in force at the as-of date" and apply only when the run's as-of equals the date they were verified for (3-Jul-2026).
* **Open calibration items left to the committee, not decided in code:** the weight of the Nestle FSSAI notice, Titan's three non-executive director resignations, and Natco's -1 anchor.
* **JB Chemicals** is back in `portfolio/universe.csv`, but `portfolio/stocks_given.tsv` (your 29-row table) is unchanged - add the row and run with `--expect-count 30`.
* The reconciled card's other numbers depend on evidence that must be retrieved live; they are targets, not something this repository can reproduce offline.
